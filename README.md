# 《谁是人机》单人可交互 Web Demo

知乎官方 Hackathon 原型：一个人即可完成阅读、三轮写作、四次投票、身份揭晓、积分结算、关系卡回看与再来一局。

当前流程为：阅读 → 第一轮写作 → 第一轮身份投票 → 第二轮写作 → 评论质量投票 → 第三轮写作 → 问题质量投票 → 最终身份投票 → 揭晓与结算。三轮内容公开后直接进入对应投票页，不再经过独立阅读页。

## 本地运行

```bash
npm install
npm run dev
```

打开 Vite 输出的本地地址。页面状态保存在浏览器 `localStorage`，刷新会恢复当前局；顶部“退出本局”或对局控制栏“重置”可清空本局并返回首页。

## 验证命令

```bash
npm test
npm run build
```

测试覆盖用户可见字符计数（含组合 emoji）、50/51 字边界、空白校验、题包预设字数与单问题约束、PRD 第 9 节计分票型、AI 选票过滤、关系卡优先级、禁止自投、投票幂等与失败重试、第三轮两次投票隔离、自动阶段切换和重新开局状态清理。

## 实现说明

- React + TypeScript + Vite 前端，使用显式阶段状态机管理流程。
- 当前用户可以实际输入、提交和投票；其余两名“真人席位”和一个“AI 席位”使用本地预设脚本。
- 三轮写作结束后直接公开内容并进入投票；前三次阅读投票合并为 40 秒，最终身份投票保留 20 秒。
- 投票卡片点选一次即提交。本地模拟服务确认前会拦截重复点击；成功后锁定，失败时留在原页重试。
- 正常流程只由统一倒计时切换阶段。提交或投票后会留在当前页直到截止，不会因其他席位提前完成而快进；折叠控制栏的“结束本阶段”仅用于模拟服务端阶段截止。
- 四席使用同一套刘看山基础形象的蓝色连帽衫、绿色背带裤、黄色针织衫和紫色运动外套变体。
- 计分只使用三名真人席位的选票，AI 单独展示且不进入真人排行榜。
- 第三轮问题质量票与最终身份票分开存储；关系卡只依据最终身份票和真实质量票生成。
- “复制”仅写入剪贴板，不会伪装成已发布到知乎。
- 当前题包来自可核对的知乎原帖，跳转入口仅在最终身份揭晓后出现。

## Demo 边界与安全限制

这是前端单人演示，并非真实匹配：没有知乎账号、多人网络、真实模型调用、排行榜、支付或平台发布接口。

身份、未公开内容、倒计时和选票目前都存在本地前端状态中，因此**不具备正式服务端的身份保密与多客户端同步能力**。当前的统一时钟和投票接口是本地模拟服务，只用于单人流程。真实多人版必须由服务端保管控制者映射、AI 身份、未公开提交和未公开选票，并由服务端完成统一计时、阶段广播、禁止自投、幂等提交与结算。
