# 《谁是人机》单人可交互 Web 版

知乎 Hackathon 项目。一个人即可完成三轮写作、三次匿名猜 AI，并在三轮结束后统一揭晓和结算。

当前流程：

1. 第一轮“为什么《牛来》能申请到龙标？”：先读题 → 写一条 50 字以内的评论 → 匿名猜 AI → 进入第二轮读题。
2. 第二轮“iPhone duo 的 duo 有什么含义？”：先读题 → 写一条 50 字以内的评论 → 重新匿名排列 → 猜 AI → 进入第三轮读题。
3. 第三轮 `#西游记`：先看主题 → 写一个 30 字以内的问题 → 再次匿名排列 → 猜 AI → 统一揭晓三轮身份并汇总成绩。

读题阶段不计时；点击“读完了，开始作答”或“开始提问”后，才启动本轮完整的 120 秒写作时间，投票各 40 秒。第一、二轮投票结束后直接进入下一轮读题页，不公开作者、AI 身份、票数或得分；第三轮投票结束后再统一揭晓。玩家主动提交；即使其他模拟席位已经准备好，也不会提前公开。

## 本地运行

```bash
npm install
npm run dev
```

打开 Vite 输出的本地地址即可。未配置模型时，游戏自动使用本地预设 AI 内容，不会阻塞开局。

如需调用兼容 OpenAI Chat Completions 协议的模型，可将 `.env.example` 复制为 `.env` 并填写：

```dotenv
AI_API_KEY=your-api-key
AI_BASE_URL=https://your-provider.example/v1/
VITE_AI_MODEL=your-model-name
```

API key 只由 Vite 代理读取，不进入浏览器代码。模型返回内容会按三轮的 50/50/30 字限制再次校验；失败时准备页会明确提示并允许重试。

生产预览：

```bash
npm run build
npm run preview
```

停止开发或预览服务时，在对应终端按 `Ctrl+C`。

默认页面不显示调试浮窗。开发环境进入任一轮后，顶部提供“下一阶段”：读题页会进入作答页；作答或投票尚未完成时会提示先完成，完成后才推进到投票、下一轮读题或最终揭晓。需要暂停、加速或使用完整调试控制时，可在本地地址后添加 `?debug=1`。

## 玩法与计分

- 每轮由三名真人角色各投一票，AI 不投票。
- 猜中当轮 AI 的真人得 2 分。
- 当轮被误认成 AI 票数最高的真人得 3 分；AI 得票多少不影响这项比较。
- 若真人全部是 0 张误认票，不发 3 分。
- 若多名真人以正票并列最高，并列者各得 3 分。这是参考稿未明确处采用的当前默认规则。
- 两项可以叠加，每轮最高 5 分，三轮满分 15 分；总分相同则并列排名。

分数始终由 `gameId` 下保存的三轮选票和匿名作者映射纯计算得出，不写入累加型积分，因此刷新不会重复结算。关系卡依赖的旧质量票和最终身份票已经取消，本版先隐藏关系卡，避免使用跨轮数据生成错误关系。

## 匿名与状态

- A/B/C/D 的席位和四套刘看山服装在一局内保持稳定。
- 投票页只显示本轮的 ①②③④、统一中性刘看山和文字；除“你写的”外，不显示作者席位或服装。
- 三轮各保存一份独立随机编号映射，下一轮不会沿用上一轮编号。第一、二轮的历史内容仍只显示匿名编号和正文；第三轮投票结束后才统一显示三轮编号对应的作者与 AI 身份。
- 选票请求使用 `gameId + roundId + contentId`，点选成功后锁定。重复请求幂等，失败可留在原页重试。
- 页面状态保存在 `localStorage`，刷新恢复当前局；“退出本局”会清理当前局。“再来一局”生成新的 gameId、席位分配、编号映射、草稿和选票。
- 三轮读题页、草稿和写作剩余时间都随当前局保存；展开或收起题目不会重建游戏状态。

## 题目、示例与来源

本轮三道题来自产品提供的机制参考，但没有提供可核实的对应原帖地址。因此界面分别标为“游戏题目”或“主题标签”，不显示虚构作者、赞数和原帖跳转。模拟席位文字只用于单人流程，不冒充知乎用户反馈。

远端合入的帖子导入模块（`src/game/posts.ts`、`public/data/initial-posts.json`）继续保留，方便未来题库接入；当前固定三轮不从该题池取题，也不会因题池加载失败阻塞首页。

用户可见文案统一维护在 [`文案总表.md`](./文案总表.md)。修改页面文字时，请在同一次改动中同步该文件。

测试覆盖：

- 组合 emoji 字符计数、50/51 与 30/31 边界、空白输入；
- 三轮独立无倒计时读题页、点击后启动的 120 秒写作、40 秒投票、前两轮匿名衔接与最终统一揭晓；

- 状态结构校验、匿名映射持久化和再来一局清理。

## 当前边界

这是本机单人模式：当前用户实际输入和投票，另外两个真人角色与一个隐藏 AI 由程序模拟。没有知乎账号、真实多人网络、排行榜、支付或平台发布接口。

身份、未公开内容、计时和选票目前都在前端状态中，因此不具备正式服务端的身份保密或多客户端同步能力。未来多人版必须由服务端保管身份映射、未公开提交和选票，并负责统一计时、幂等校验与结算。
